# Remove Narration Comments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Delete every code comment and every lint/type ignore in pigeon, keeping only directives a build needs, with comment-only commits proven comment-only.

**Architecture:** Three fix commits first (they replace `Record<string, any>` in the fixture helpers, which lets their `eslint-disable` lines go and keeps lint green), then four comment-only commits, one per area. A checker compares each file before and after with comments stripped from the TypeScript AST; non-JS files may only lose comment or blank lines.

**Tech Stack:** TypeScript 5.9 (backend, frontend, e2e), ESLint 10 + typescript-eslint, Vitest 5, Vite 8, Playwright 1.65, Firebase emulators.

**Spec:** the approved task brief (2026-11-21, strictest version): no comments at all; keep only `//go:build`, `//go:embed`, `/// <reference`, shebangs, license headers; remove every lint/type ignore and fix the code; don't touch generated/vendored files or docs.

## Global Constraints

- Delete every comment, including warnings, JSDoc, commented-out code and test comments. No new comments anywhere.
- Keep only build directives (the keep-list below). No license headers exist outside the excluded vendored file.
- No `eslint-disable*`, `biome-ignore`, `@ts-ignore`, `@ts-expect-error`, `nolint` may remain; none may be added.
- Comment-removal commits are comments-only. Fix commits pass the full suite.
- Where a deleted comment warned about a real trap, add no code; list it in the PR body under "Traps that lost their comment".
- Never touch `~/ghq/github.com/hokita/pigeon`. Never merge. Merging to main deploys production.

## Traps that lost their comment (draft for the PR body)

- `backend/src/app.ts:18`: `cors` sends no CORS headers when `origin` is undefined, so `'*'` is set explicitly.
- `backend/src/config/firebase.ts:3`: local `verifyIdToken()` needs the project ID passed explicitly.
- `backend/src/items/store.ts:55`: Firestore transactions need every read before the first write.
- `backend/src/items/store.ts:149`: the UI tree is stored as JSON text because Firestore can't hold nested arrays.
- `backend/src/mcp/server.ts:106`: `express.json()` already consumed the body, so it's passed to the transport.
- `backend/src/middleware/apiToken.ts:23`: digests are compared so `timingSafeEqual` gets equal lengths.
- `backend/src/middleware/rateLimit.ts:5`: the limit is per Cloud Run instance.
- `backend/src/routes/items.ts:11`: never log the request; its headers carry the ID token.
- `backend/vitest.db.config.ts:3`: db tests run serially because they share emulator data.
- `backend/.env.example:8`: `PIGEON_MCP_TOKEN` needs 43+ chars or MCP stays off.
- `frontend/src/csp.test.ts:69`: a new production API origin must be added to `connect-src` in `firebase.json`.
- `frontend/src/generative-ui/guard.ts:47`: own entries only, so a stored type such as `toString` can't reach `Object.prototype`.
- `frontend/src/generative-ui/Markdown.tsx:5`: no `rehype-raw`; raw HTML must stay escaped.
- `frontend/src/testing/cspRule.ts:20`: no wildcard origins, because `*.run.app` would allow other people's services.
- `frontend/src/generative-ui/{limits,library,safeUrl,canonicalUrl}.ts(x)`, `frontend/src/types.ts`: each must stay in sync with its backend twin.
- `e2e/playwright.config.ts:24`: the emulator needs SIGTERM; SIGKILL orphans the Java Firestore emulator on :8181.
- `e2e/global-setup.ts:21,61`: `EMAIL_EXISTS` on reruns; `emailVerified` is honored only from a privileged caller.
- `firestore.rules:3`: deny-all is intentional, since only the Admin SDK (which bypasses the rules) touches Firestore.
- `.github/workflows/backend.yml:73`: `PIGEON_MCP_TOKEN` is wired only once the repo variable exists.
