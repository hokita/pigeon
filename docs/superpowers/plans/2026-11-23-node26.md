# Node 26 LTS (26.13.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every place pigeon sets or assumes a Node version moves from 24.22.3 to 26.13.1 (deployed Cloud Run image, CI, local Volta pins, Node-tied deps, pin check, docs), proven on Node 26 before the PR and checked in production after merge.

**Architecture:** One pin value, enforced by `scripts/check-node-pins.sh` (run in CI). The pin-check tests move to 26.13.1 first (red), then every pin moves (green). `@types/node` moves to 26 with regenerated lockfiles. All Node 26 runs on the Mac happen inside Docker containers, so Volta never fetches a runtime on the Mac.

**Tech Stack:** Node 26.13.1 (npm 11.20.0), Docker `node:26.13.1-alpine`, GitHub Actions `setup-node`, Volta, TypeScript 5.9.3, Vitest 5.1.0, Playwright 1.65.1, firebase-tools 15.36.0 (emulators) and 15.22.1 (deploys).

**Spec:** the task brief of 2026-11-23 and the survey `/tmp/node26-survey/REPORT.md` section 2.4 (the brief names `pigeonRT.md`; that file does not exist, `REPORT.md` is the only file there). Every survey claim below was re-checked against `origin/main` `a3d4a4a` and live sources on 2026-11-23.

Verified on nodejs.org/dist/index.json 2026-11-23: v26.13.1, 2026-11-10, `security: true`, LTS "Lithium"; newest 26.x and newest security release. Re-check index.json right before the commit; if a newer 26.x security release exists, use it instead.
- Docker base: `node:26.13.1-alpine@sha256:6bd9ab43c0ec0190ca7b2d193906cb8b7edf6e7f4afa43ddeccd6452710bffb5` (Docker Hub index digest, 2026-11-23). Re-resolve right before the commit; the digest moves on rebuilds.

- Keep the Dependabot `ignore` rule for `node` `version-update:semver-major` (`.github/dependabot.yml:21-24`).
- No code comments. No lint or type rule disabled.
- No project IDs, backend URLs, keys or emails added to the repo or PR text. Existing workflow lines that contain them are left untouched.

- Never merge, never comment on GitHub. English for commits, PR title and body.

## Review Focus

1. **Volta auto-fetch on the Mac.** Once a `package.json` pins `26.13.1`, running `node`/`npm`/`npx` through Volta's shims anywhere under the worktree downloads Node 26.13.1 into `~/.volta`. Expected: after Task 2 starts, every Node command runs in a container (`scripts` in Task 4 show how); a reviewer checks `volta list all` still shows no 26.x at the end.
2. **Linux `node_modules` leaking into the worktree.** Containers mount the worktree; a bind-mounted `node_modules` would leave Linux binaries (esbuild, re2, rollup) that break Mac dev. Expected: containers copy the tree to `/work` or mount `node_modules` as an anonymous volume; `git status` after verification shows only intended files, and no `node_modules` appears in the worktree.
3. **firebase-tools on Node 26.** Every firebase-tools release (15.22.1 used by deploys, 15.36.0 in devDeps, latest 15.37.0) depends on `superstatic ^10` (engines `20 || 22 || 24`). Expected: `npm ci` prints `EBADENGINE` for superstatic as a warning only (no `.npmrc`/`engine-strict` in the repo) and the emulators and `npx -y firebase-tools@15.22.1 --version` run on 26. Task 4 runs both.
4. **Native/ABI deps.** `re2` 1.27.1 (optional, via firebase-tools) is ABI-bound; Node 26 is ABI 147. Verified: re2 1.27.1 engines `^22.22.2 || ^24.15.0 || >=26.0.0` and its release ships `linux-x64-147`, `linux-musl-*-147`, `darwin-arm64-147`. Expected: `npm ci` on 26 fetches the prebuilt without compiling; if it falls back to node-gyp and fails, it is optional, so install still succeeds and the emulator test in Task 4 shows whether that matters.
5. **Node 26 semver-major removals in transitive deps.** Removed: `http.Server.prototype.writeHeader()`, legacy `_stream_*` modules, `--experimental-transform-types`; `module.register()` runtime-deprecated; DEP0182 end-of-life; Undici 8; ABI bump. Repo source has no hit for any of them (`git grep` 2026-11-23). Transitive use (express 5, MCP SDK, firebase-admin, tsx, vitest) can only be ruled out by running: Task 4 runs unit, emulator, e2e and the built image on 26, and greps their output for `DeprecationWarning` / `ERR_` / `MODULE_NOT_FOUND`.

## Deploy verification (after the owner merges)

Merging to `main` deploys. This PR touches `backend/**`, `frontend/**`, `.github/workflows/backend.yml`, `frontend.yml` and `firestore-rules.yml`, so three deploy workflows run.

1. **Deploy backend** (`backend.yml`): lint, test and build on 26, then the image is built from `node:26.13.1-alpine@<digest26>` and pushed as `:latest`, and `gcloud run deploy pigeon-backend` runs. Check the run is green.
2. **Deploy to Firebase Hosting** (`frontend.yml`): the build runs on 26 and the deploy uses `firebase-tools@15.22.1` on 26. Check it's green and the log has no error beyond the superstatic warning.
3. **Deploy Firestore rules and indexes** (`firestore-rules.yml`): it redeploys unchanged rules and indexes with firebase-tools 15.22.1 on 26. Check it's green.
4. **Deployed Node version:** dispatch `Audit (nightly)` (`gh workflow run audit-nightly.yml --ref main`). In the `Deployed image (backend)` job, the "Check deployed Node version" step prints `Node v26.13.1 is the latest security release of v26`, and Trivy passes on the deployed image.
5. **Live smoke:** `GET <backend>/health` returns `{"ok":true}`. `POST <backend>/mcp` without a token returns the same status code as before. The Hosting site loads, sign-in works, and the feed lists items. In Cloud Run logs, the new revision shows `Listening on port 8080` and no `DeprecationWarning` / `ERR_`.
6. **Rollback** if any check fails: `gcloud run services update-traffic pigeon-backend --region asia-northeast1 --to-revisions <previous revision>=100`. Then revert the PR, which redeploys 24.22.3 through the same workflows.
